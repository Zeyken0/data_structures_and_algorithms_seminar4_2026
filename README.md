# Внешние сортировки (Семинар 4)

Реализация трёх алгоритмов внешней сортировки на C++ с модульными тестами
(Catch2 v2). Все алгоритмы работают с данными во **внешней памяти**: записи
хранятся в последовательных (двоичных) файлах, доступ к ним — только
последовательный, а в ОП помещается не больше одной серии записей.

## Алгоритмы

### 1. Двухфазная сортировка прямым слиянием (`two_phase_merge_sort`)

Используется три файла: `f` (исходный) и два вспомогательных — `g` и `t`.
Каждый проход состоит из двух фаз:

1. **Фаза разделения** — серии из файла `f` попеременно распределяются по
   файлам `g` и `t` (первая серия — в `g`, вторая — в `t`, третья — в `g` и т.д.).
2. **Фаза слияния** — серии файлов `g` и `t` сливается попарно обратно в `f`,
   при этом длина серий удваивается.

Проходы повторяются, пока в файле `f` не останется одна серия.

Пример (длина серии 1, исходный файл `f: 3 14 15 9 2 5 17 -4 0`):

```
Разделение: g: 3 15 2 17 0    t: 14 9 5 -4
Слияние:    f: 3 14 | 9 15 | 2 5 | -4 17 | 0
Разделение: g: 3 14 | 2 5 | 0    t: 9 15 | -4 17
Слияние:    f: 3 9 14 15 | -4 2 5 17 | 0
...
Слияние:    f: -4 0 2 3 5 9 14 15 17
```

### 2. Однофазная сортировка прямым слиянием (`one_phase_merge_sort`)

Используется четыре файла: два исходных `f1`, `f2` и два результирующих
`g1`, `g2`. Отдельной фазы разделения нет — чтение серий, их слияние и запись
результата составляют **единый проход**:

1. Из файлов `f1` и `f2` читается по одной серии.
2. Эти серии сливается.
3. Полученная серия попеременно дописывается к файлу `g1` или `g2`.
4. Файлы `f1`, `f2` освобождаются, пары файлов меняются ролями
   (`f1 = g1`, `f2 = g2`), после чего шаги 1–4 повторяются, пока не получим
   файл с одной серией.

### 3. Сортировка естественным слиянием (`natural_merge_sort`)

Используется три файла: `f` (исходный) и два вспомогательных — `g` и `t`.
В отличие от прямого слияния длина сливаемых серий **не фиксируется**:
серии берутся ровно такими, какими их задают данные (максимальные неубывающие
последовательности), поэтому частично упорядоченные данные обрабатываются
быстрее.

1. **Фаза распределения** — естественные серии файла `f` попеременно попадают
   в файлы `g` и `t`.
2. **Фаза слияния** — серии файлов `g` и `t` сливается попарно обратно в `f`.

Проходы повторяются, пока в файле `f` не останется одна серия.

### Ускорение прямого слияния

Для двух прямых сортировок доступен параметр `run_size`: блоки из `run_size`
записей сортируются в ОП и во внешнюю память попадают уже в виде серий длиной
`run_size`, поэтому процесс слияния начинается сразу с серий такой длины.
Значение по умолчанию — 1 (классическая схема из лекции).

## Структура проекта

```
external_sorting/
   include/
       two_phase_merge_sort.h
       one_phase_merge_sort.h
       natural_merge_sort.h
       merge_utils.h          # общие средства: потоки записей, слияние серий
   src/
       two_phase_merge_sort.cpp
       one_phase_merge_sort.cpp
       natural_merge_sort.cpp
tests/
   test_two_phase_merge_sort.cpp
   test_one_phase_merge_sort.cpp
   test_natural_merge_sort.cpp
   test_utils.h
```

## Стек

- C++17
- CMake 3.16+
- Catch2 v2 (vendored, в `external/catch2`)

## Сборка

```bash
cmake -S . -B build
cmake --build build
```

## Запуск тестов

```bash
./build/tests/sorting_tests
```

или через CTest:

```bash
ctest --test-dir build --output-on-failure
```

Тесты покрывают граничные случаи (пустой файл, один элемент, уже
отсортированный файл, обратный порядок, дубликаты, отрицательные числа,
«хвост» серии, случайные массивы), а также сверяют результат с `std::sort`
для типов `int`, `double` и `float`.
